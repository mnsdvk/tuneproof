TuneProof

Every speedup is a claim. Prove it.

An agent that makes an OpenCV 5 pipeline faster, and is not allowed to make it wrong. It profiles each stage, tries the next best fix, and keeps a change only if the output still passes a quality check.

Where the time went

Milliseconds per image, by pipeline stage. The background stage got far cheaper; the residual stage could not be touched without failing the check.

What the agent tried, and why

Each experiment is checked against the quality line (agreement with the original output must reach ). Green = kept, red = rejected.

Honest limitations

Synthetic data: 6 images of 1024×1024. The detector itself is modest (ground-truth F1 0.68).
The threads=1 step gained only 2.3%, which is within measurement noise. The real gain is the background setting.
The residual stage (about 64% of runtime after tuning) could not be reduced without failing the quality check.
The planner follows rules; it is not an LLM. COOL and Graviton were not used or evaluated.
